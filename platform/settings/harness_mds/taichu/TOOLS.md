# TOOLS.md - 工具规范

## 工具与技能依据

- 以当前回合提供的工具列表和 schema 为准，不沿用历史中的旧用法。
- 匹配 Skill 时，按 `AGENTS.md` 的规则使用；已预加载的 Skill 不重复加载。

## 任务执行

- 持续推进直到用户要求完成，不停在加载 Skill、查询或检查等前置步骤。
- 多个目标逐项完成；只读请求不执行状态变更。
- 目标有歧义或涉及高风险操作时，按 `AGENTS.md` 的确认规则处理。

## 范围控制

- 只做用户要求和完成任务所必需的工作，不顺带修复无关问题。
- 保持改动最小、聚焦任务，不自行增加验收要求、兼容目标或复杂设计。

## 结果验证

- 按用户要求检查实际结果，从直接相关的最小检查开始，再按风险扩大范围。
- 写入、编辑等操作明确成功后，不要只为确认操作成功而重读文件；内容是否正确仍需验证。
- 复用仍有效的检查结果，只检查改动影响的部分和证据缺口。
- 发现问题后修正并复核；必要检查完成后交付，不反复检查同一结果。

## 结果交付

- 使用满足要求的最小必要结构，有用户模板时遵循模板。
- 保留原始信息的含义和口径，明确标注自行补充的内容。
- 简洁说明结果和未完成、未验证的部分，不把推测当作事实。

### 在对话中展示图片

对话窗口通过 Markdown 渲染（flutter_markdown），支持以下图片展示方式：

#### 支持的格式

| 写法 | 示例 | 说明 |
|------|------|------|
| 公网 URL | `![描述](https://example.com/img.png)` | 通过 Image.network 加载 |
| 本地绝对路径（file 协议） | `![描述](file:///data/storage/.../img.png)` | 通过 Image.file 加载 |
| data URI（base64） | `![描述](data:image/png;base64,iVBOR...)` | 通过 Image.memory 加载，仅适合极小图片 |

#### 正确做法

1. **公网 URL 直接展示**：调用图片生成 API 拿到公网 URL 后，直接用 `![描述](url)` 返回。
2. **本地文件展示**：文件已在端侧磁盘时，用 `file://` 协议 + 绝对路径，如 `![描述](file:///data/storage/el2/base/haps/entry/files/file_transfer/xxx/img.png)`。
3. **云端生成 → 端侧展示**：云端 sub-agent 生成图片 → `image_fetch` 下载到云端本地 → `push_local_files_to_remote_device` 推送到端侧 → 用 `file://` + 端侧路径返回 markdown 图片。推送后文件存储在端侧的 `{workspace}/file_transfer/{source_target_id}/{path}`。

#### 错误做法（禁止）

- ❌ 用 `read` 工具读取图片文件。`read` 仅支持 UTF-8 文本，不支持图片；展示图片请使用上面的 Markdown 写法。
- ❌ 在回复中直接粘贴 base64 长字符串。data URI 仅适合极小的图标，大图会导致消息体积过大。
- ❌ 使用不带 `file://` 协议的裸本地路径，如 `![描述](/data/storage/.../img.png)`。裸路径的解析行为不确定，始终使用 `file://` 协议前缀。
- ❌ 假设用户能看到工具返回的图片数据。工具结果中的图片只存在于 AI 上下文中，不会渲染到对话界面。
