# 实例详情「输出」页使用说明

> 适用页面：`/#/instance/<instance_id>?tab=outputs`
>
> 本文面向平台使用者，说明页面各区域展示什么、数据如何理解，以及常见误区。
>
> 最后更新：2026-10-28

## 1. 这个页面用来做什么

「输出」页用于查看一个批跑实例的会话分析结果，主要回答以下问题：

1. 当前有多少会话已经完成浅层分析？
2. 会话分别落在哪个 L0～L3 等级？
3. 哪些会话出现了 Task-DONE、评测结果和 Completion？
4. 当前使用了哪些 Agent、用户模拟器和 Evaluator 模型？
5. 某个会话的轨迹、日志、评测内容和沙箱交付物在哪里？

页面由四个主要区域组成：

```text
会话漏斗
  ↓
模型配置 / 用户模拟配置
  ↓
状态分析（浅层分析 → 交付物下载）
  ↓
会话列表（逐条查看）
```

建议先看顶部整体分布，再看状态分析确认数据是否处理完整，最后到会话列表定位具体问题。

***

## 2. 会话漏斗

### 2.1 数字代表什么

漏斗区域展示当前实例在 `task_records` 中的会话记录，并按最终 `traj_level` 分组：

| 显示项   | 含义                             |
| ----- | ------------------------------ |
| L0～L3 | 已完成浅层分析，并得到对应最终等级的会话数          |
| 未评估   | `traj_level` 仍为空，尚未被浅层分析处理的会话数 |
| 已定级   | L0、L1、L1.5、L2、L3 的数量之和         |
| 会话总数  | 当前实例在 `task_records` 中的记录总数    |

注意：页面柱高用于辅助比较，不应直接当作通过率：

* L0～L3 柱高以“已定级数量”为基数计算。
* “未评估”柱高以“会话总数”为基数计算。
* 数量为 0 时，柱顶数字可能留空。

### 2.2 L0～L3 的判定口径

L0～L3 是**互斥的最终等级**，每条会话只会落入一个等级，不是逐级累计值。

| 等级   | 当前代码口径                    | 怎么理解           |
| ---- | ------------------------- | -------------- |
| L0   | 未通过基础交互门槛                 | 有轨迹，但有效交互不足    |
| L1   | 通过基础门槛，但没有数值型 Completion  | 有有效过程，暂时没有可用评分 |
| L1.5 | 有数值型 Completion，且 `< 0.5` | 已评测，但完成质量较低    |
| L2   | `0.5 <= Completion < 1.0` | 部分或较高程度完成      |
| L3   | `Completion >= 1.0`       | 达到满完成度         |

基础门槛因 Harness 类型不同而略有差异：

* OpenClaw 族：工具调用数不少于 3，并且至少有一轮普通交互。
* 其他 Harness：至少有一轮普通交互。

缺少有效轨迹统计、但主日志出现权威 `【Task_Done】` 标记时，系统会使用日志兜底：最低按 L1.5 处理；若还能解析出 Completion，则可继续升为 L2 或 L3。

### 2.3 “浅层分析待处理”进度条

进度条出现时，表示仍有 `traj_level IS NULL` 的会话等待处理。

* `已定级`：成功得到 L0～L3 的数量。
* `分级失败`：浅层 worker 已处理过，但未能得到有效等级，数据库中记为 `failed`。
* `未评估`：尚未处理，数据库中仍为 `NULL`。
* 进度百分比：`(已定级 + 分级失败) / 会话总数`。

因此，“浅层已完成”表示所有记录都处理过，**不代表所有记录都成功得到了 L0～L3**。如果漏斗柱数量之和小于会话总数，应再用会话列表的“未分级”筛选查看失败记录。

### 2.4 刷新与导出

* “刷新”：立即重新读取数据库统计和当前页会话列表，不会清空已有结果。
* “导出 Excel”：导出当前实例的 L0～L3、未评估、`failed` 和总计数据。

该按钮导出的是单实例会话漏斗，与“队列与任务管理”里的批量任务导出不是同一个文件。

## 3. 模型配置 / 用户模拟配置

该区域展示任务创建时保存的连接信息，一般包含三类角色：

* 主 Agent
* 用户模拟
* Evaluator

### 3.1 字段说明

| 字段          | 含义                                        |
| ----------- | ----------------------------------------- |
| 名称          | 模型在任务中的角色                                 |
| BASEURL     | 请求模型时使用的服务地址                              |
| KEY 后四位     | API Key 的后四位，仅用于确认使用了哪一把 Key；页面不会展示完整 Key |
| 代理名称        | 根据代理地址映射出的内部代理名，未匹配时为空                    |
| 模型          | 任务创建时配置的模型名称                              |
| 浏览          | 打开该角色对应的外部会话浏览页                           |
| 导出          | 向外部会话导出服务提交导出任务                           |
| 导出状态        | 未导出、排队中、运行中、完成或失败                         |
| 导出路径        | 外部导出任务成功后返回的会话路径                          |
| 导出的会话数      | 外部服务报告的导出数量                               |
| 启动时间 / 结束时间 | 当前平台实例的开始和结束时间，不是单次模型请求耗时                 |

### 3.2 两个“导出 Excel”不要混淆

* 会话漏斗右上角“导出 Excel”：导出分级统计。
* 模型配置区域“导出 Excel”：导出当前表格中的模型连接信息，Key 仍只保留后四位。

模型配置表每行的“导出”按钮则是提交外部会话导出任务，并非下载上述 Excel。

## 4. 状态分析

状态分析区域展示两段处理流程：

```text
浅层分析 → 交付物下载
```

### 4.1 浅层分析状态

| 状态     | 含义                     | 建议操作                   |
| ------ | ---------------------- | ---------------------- |
| 暂无会话数据 | 尚未产生 `task_records`    | 确认任务是否已经开始产出           |
| 未分析    | 已结束实例仍有未评估会话           | 操作员可提交浅层分析             |
| 浅层分析中  | 已进入 worker 队列          | 等待处理并观察进度              |
| 自动分级中  | 实例仍在 running/preparing | 无需手动提交，worker 会持续采集    |
| 浅层已完成  | 没有待处理的 NULL 记录         | 可查看会话详情；仍可能存在“未分级”失败记录 |

已结束的实例进入输出页后，如果仍有未评估记录，前端会幂等登记一次浅层分析请求。重复进入页面不会重复制造多份任务。

### 4.2 交付物下载状态

该进度来自“沙箱交付物”使用的同一套下载队列：

| 状态  | 含义                   |
| --- | -------------------- |
| 已下载 | 文件已落到平台本地缓存，可打开详情    |
| 下载中 | worker 正在下载          |
| 待下载 | 已发现但尚未领取             |
| 失败  | 下载失败，或达到重试限制后被跳过     |
| 空目录 | OBS 前缀存在，但沙箱没有产出任何文件 |

“交付物总数”和“会话总数”来自不同数据源，不能要求两者相等。空目录会计入交付物总数，但当前状态卡不会单独显示空目录数量，所以分项之和偶尔也可能小于总数。

## 5. 会话列表

会话列表用于逐条检查某个配置/会话的结果。默认每页读取 50 条，后端完成分页、筛选和排序。

### 5.1 筛选与搜索

* 等级筛选：L0、L1、L1.5、L2、L3、未评估、未分级。
* 未评估：`traj_level IS NULL`，尚未处理。
* 未分级：`traj_level = 'failed'`，处理过但没有得到有效等级。
* 搜索会话：按完整 `config_name` 模糊搜索，输入后约 300ms 发起查询。
* Completion 和评分支持点击表头排序。

### 5.2 各列含义

| 列             | 数据来源与含义                               | `—` / `-` 的含义                        |
| ------------- | ------------------------------------- | ------------------------------------ |
| 任务名称          | 从 `config_name` 中提取的展示名称；鼠标悬停可看到完整会话名 | 无                                    |
| 等级            | `task_records.traj_level`             | “未评估”表示 NULL；“未分级”表示 failed          |
| Completion    | Evaluator 给出的完成度，页面按百分比显示             | 没有数值型 Completion                     |
| Task-DONE     | 日志或轨迹中检测到任务完成标记时显示 `✓`                | 没检测到该标记                              |
| 工具失败          | 预留的工具调用失败展示列                          | **当前版本没有有效数据源，恒显示 `—`，不能据此断言工具没有失败** |
| Eval-OC-Trace | `has_eval`，表示是否解析到 Evaluator 评测记录     | 没解析到评测记录                             |
| 评分            | `task_records.eval_score`，保留 4 位小数    | 没有评分                                 |
| 操作            | 打开详情，或进入对应沙箱交付物                       | 无                                    |

### 5.3 Task-DONE 应该怎么理解

Task-DONE 是会话内容中的完成信号，主要来源是主日志中的权威标记 `【Task_Done】`。旧版 Harness 的“所有任务执行完成!”只有在平台任务状态同时为成功时才会被采信。

Task-DONE 与以下概念不同：

| 概念         | 表示什么                   |
| ---------- | ---------------------- |
| Task-DONE  | Agent/模拟器在会话内容中声明任务已完成 |
| Completion | Evaluator 对完成程度给出的数值   |
| 评分         | 评测缓存或离线分析写入的评分字段       |
| 平台任务成功     | Hive 执行层将该 task 记录为成功  |
| 实例已结束      | 整个批跑实例不再运行             |

所以可能出现：

* 有 Task-DONE，但没有 Completion：任务声明完成，但没有数值型评测结果。
* 有 Completion，但没有 Task-DONE：Evaluator 给出了结果，但日志中没有完成标记。
* 平台任务成功，但评分较低：执行流程成功结束，不代表任务质量高。

### 5.4 Completion 和评分的颜色

页面目前使用相同的颜色阈值：

* `>= 0.5`：绿色。
* `> 0 且 < 0.5`：橙色。
* `= 0`：红色。
* 无值：灰色并显示 `-`。

Completion 以百分比显示，例如 `0.8889` 显示为 `88.9%`；评分以小数显示，例如 `0.8889`。

## 6. 会话详情与交付物

点击“任务名称”或“详情”，页面会先从平台本地缓存读取交付物，不会直接在线读取 OBS。

### 6.1 本地已有交付物

详情弹窗包含：

* 摘要：Harness、是否已评测、Task-DONE、轨迹下载状态、Completion、工具调用/轮次统计。
* “轨迹”：Assistant 消息、thinking、toolCall、toolResult 以及非零退出码。
* “Log”：主日志、Gateway 日志、Eval 日志。
* “评测”：Evaluator 轨迹、Completion 和 Task-DONE。

### 6.2 本地没有交付物

详情会提示“该任务的交付物尚未下载到本地”。操作员可以点击“下载交付物后重试”：

1. 将该任务加入高优先级交付物下载队列。
2. 页面每 3 秒查询一次下载状态。
3. 下载完成后自动重新打开详情。

若提示“该任务没有产出交付物”，表示 OBS 上对应前缀为空，反复重试通常不会产生新文件。

点击“交付物”或详情弹窗底部“查看交付物”，会切换到实例的“沙箱交付物”页并定位到相应任务。

***

## 7. 自动刷新机制

* 实例基础状态：每 10 秒刷新。
* 输出页浅层统计和当前会话列表：停留在输出页时每 10 秒刷新。
* 交付物进度：进入或切回输出页时读取；当前不会随浅层统计每 10 秒自动更新。
* 外部会话导出状态：存在 queued/running 任务时每 5 秒刷新。
* 单会话交付物下载：用户主动请求后每 3 秒刷新。

离开输出页后，相关轮询会停止，避免无意义请求。

## 8. 结合示例页面怎么看

以实例 `2610281135-c008450182610281134-faf6` 在 2026-10-28 的页面快照为例：

* 会话总数：192。
* L1.5：33，L2：14，L3：46，L0/L1：0。
* 已定级：`33 + 14 + 46 = 93`。
* 未评估：1。
* 页面进度显示“已定级 93 / 192”，但只剩 1 条未分析。

这意味着其余 `192 - 93 - 1 = 98` 条已经被 worker 处理，但落为 `failed`，因此没有显示在 L0～L3 柱中。可在会话列表选择“未分级”查看这些记录。

页面中部分 L1.5/L2/L3 行显示 Task-DONE `✓`，说明检测到了完成标记；它不能单独证明评分为满分。L3 行通常同时显示 `100.0%`，而 L1.5 行可以有 Task-DONE 但 Completion 为 `-`，这正体现了“完成标记”和“数值评测”是两个独立信号。

该实例同时显示交付物 `0 / 8504`、待下载 8504。这个 8504 是交付物发现队列的数量，不是上面的 192 条会话总数，两者不应直接相减或计算比例。

## 9. 常见误区

1. **L3 不是 L2 的子集数字。** 页面保存的是每条会话的最终等级，L0～L3 互斥。
2. **Task-DONE 不等于平台执行成功。** 一个是内容标记，一个是执行状态。
3. **“浅层已完成”不等于全部成功分级。** `failed` 也算已经处理。
4. **未评估和未分级不同。** 未评估是还没处理，未分级是处理失败。
5. **会话总数、任务总数、交付物总数口径不同。** 不要直接互相比较。
6. **工具失败列当前不可用于结论。** 它是预留列，现版本固定显示 `—`。
7. **看不到详情不代表没有会话记录。** 详情依赖交付物先下载到本地。

## 10. 常见问题排查

### 页面显示“暂无会话数据”

检查实例是否已经开始运行、是否产生了 `task_records`，以及 output worker 是否正常运行。

### 实例结束了，但仍有“未评估”

等待自动登记的浅层任务被 worker 消费；操作员也可以点击“提交浅层分析”。若长期不动，检查 shallow worker 状态和日志。

### 大量记录显示“未分级”

这通常表示轨迹统计文件缺失、无有效轨迹或解析失败。先打开具体会话详情、主日志和 Eval 日志判断原因。

### 点击详情后提示交付物未下载

点击“下载交付物后重试”，或进入“沙箱交付物”页请求下载。若最终显示空目录，说明沙箱没有实际产出文件。

### 模型导出长期停在排队中/运行中

模型会话导出由外部导出服务处理。先刷新状态；若仍不变化，检查外部导出服务及平台配置的 `EXPORT_BASE`。
