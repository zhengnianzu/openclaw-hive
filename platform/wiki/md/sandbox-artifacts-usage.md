# 沙箱交付物使用说明

沙箱里的 agent 跑完一个任务，会在工作目录里留下文件——图片、PPT、Excel、网页、代码、日志。**沙箱交付物**就是把那些文件拉回平台、能直接在线看的入口。

入口在**实例详情页 → 「沙箱交付物」tab**。

## 一、界面是三栏

打开 tab 后，从左到右：

| 栏位 | 作用 |
|---|---|
| **任务列表** | 这个实例的所有 sub-task，一行一个 |
| **文件导航** | 选中任务后，它的文件树 |
| **预览** | 选中文件后，右边直接看内容 |

顶部右上角有刷新按钮，任务列表下方有一行统计：**已下载 X / 已完成 Y / 共 Z**。

## 二、怎么用：点两下

### 第一下：点任务

在左栏点一个任务名：

- **已下载**（后面有绿色 ✓）→ 直接展开它的文件树
- **未下载** → 立刻排进下载队列，状态先变「排队中」

下载很快，单个任务中位数约 **1.6 秒**（P90 2.2 秒）。下完会自动加载文件树，不用手动刷新——界面每 2 秒查一次状态，好了自己就开了。

### 第二下：点文件

文件树里点任意一个文件，右边就出预览。

## 三、哪一列是什么状态

左栏每个任务后面可能显示这些词：

| 状态 | 含义 | 能点吗 |
|---|---|---|
| **✓**（绿色对勾） | 已经下到本地，可以看了 | ✅ |
| 排队中 | 已入队，等 worker 领取 | ✅（可再点，会重新排队） |
| 下载中 | 正在从 OBS 拉取 | ✅ |
| 未完成 | **这个任务还没跑完**，沙箱里还没有产出 | ❌ 置灰 |
| 无产出 | 任务跑完了，但沙箱一份文件都没上传 | 看情况 |
| 下载失败 | 网络/权限等真故障，鼠标悬停能看到原因 | ✅（点了重试） |
| 已跳过 | 重试次数用尽，或单个任务超过 2 GiB | ✅（点了重试） |
| 体积超限 | 超过单任务上限（默认 2 GiB），已从磁盘删除 | ✅ |

**「未完成」和「无产出」要分清**：

- **未完成** = 任务还在跑 / 跑挂了，OBS 上根本没有这个目录。等它跑完再看。
- **无产出** = 任务跑完了（在 `complete.jsonl` 里），但沙箱确实没写出任何文件。这是**正常情况**，不是平台故障——agent 跑失败了、或者任务本身不产生文件，都会这样。

> 之前这两种情况都会被显示成「下载失败」，现在拆开了：「无产出」是终态，不会再重试；只有真故障才标「下载失败」。

## 四、文件导航的两种视图

第二栏顶部可以切换：

**目录视图**：按真实目录结构展开，适合「我知道文件在哪」的情况。

**分组视图**：按**文件类型**自动归类，适合「我只想找那个 PPT」。分组有：

```
全部 · HTML · 文档/表格 · PDF · 图片 · 数据 · 文本 · 其它
```

每个分组后面带文件数。点分组名可以筛选。

两种视图共用同一个搜索框：「搜索文件名、扩展名」。

> 文件特别多的任务（几万个）列表会被**截断**，顶部会提示「文件过多，列表已截断」。这种情况建议直接下载整包。

## 五、预览支持哪些格式

右边预览区能直接看：

| 格式 | 怎么显示 |
|---|---|
| **HTML** | 渲染成网页（在沙箱 iframe 里，脚本能跑但拿不到平台登录态） |
| **Markdown** | 渲染成富文本 |
| **图片** | png / jpg / gif / svg / webp 等直接显示 |
| **PDF** | 浏览器内置阅读器 |
| **表格** | csv / tsv 渲染成表格 |
| **JSON** | 缩进格式化 + 语法高亮 |
| **JSONL / NDJSON** | 逐行解析，每条一个块，默认显示 5 条，可点「加载更多」 |
| **Office** | pptx / docx / xlsx → 需服务器装了 LibreOffice，转成 PDF 预览。没装的话点「转换并预览」会提示 |
| **纯文本** | 日志、代码、配置文件直接读 |

预览区上方还有三个 tab：

- **预览** —— 上面说的渲染结果
- **原始内容** —— 未经处理的源文本
- **属性** —— 文件名、相对路径、大小、修改时间、所属分组

右上角三个按钮：**复制**（复制文件路径）、**下载**、**全屏**。

### 几个注意事项

- **大文件不能在线预览**：超过 64 MB 的返回「文件过大，请下载查看」。这是防止把服务进程的内存打爆。
- **Office 首次转换会慢**：服务器端转换上限 180 秒，但前端请求 30 秒就超时了。所以第一次点「转换并预览」可能显示失败，**再点一次就好了**——转换结果已经缓存，第二次直接读。
- **HTML 里的图片**：预览时会自动把同目录的图片一起取回来，所以带图报告的 HTML 能正常显示。

## 六、背后的机制（想知道为什么慢/快时看）

### 文件从哪来

沙箱跑任务时把产物写在 OBS 上，路径形如：

```
obs://<bucket>/<owner>/<批次名>/<task名>/
```

平台把它整目录拉到本地缓存：

```
OUTPUT_CACHE/<批次名>/<task名>/
  ├─ agents/  logs/  workdir/  workspace/  workspace-evaluator/
  └─ <task名>/     ← OBS 的父子层被保留
```

**会话详情读的是同一个目录**——所以下载一次，工作区和会话详情都能用。

### 谁来下载

平台跑三个 worker 进程：

| worker | 职责 | 触发方式 |
|---|---|---|
| **浅层分级** | 算轨迹等级、填会话列表 | running 实例持续跑 |
| **产物下载（积压）** | 批量缓存最近任务 | 自动，按队列 |
| **实时下载** | **只处理你点过的任务** | 你点任务行的那一刻 |

**为什么要两个下载 worker**：积压队列可能有几万条待下，一轮要几十秒。你点的任务如果排在同一个队列里，就得等。所以实时 worker 只领「用户点过」的高优先级任务，2 秒轮询一次，不跟积压抢线程。

### 为什么有的任务列表是空的

自动缓存只覆盖**最近 1 天有活动的、且已结束的实例**。历史实例不会自动下——打开它们的工作区时，平台会现读一次该实例的完成清单，把任务列出来，然后你点哪个下哪个。

如果连任务都不显示，通常是这个实例还没有任何任务跑完。

## 七、常见问题

**Q：点了任务，一直在「排队中」？**
先看右上角刷新一下。如果还是排队中，检查实时下载 worker 是否在跑：`./run.sh worker-status`。不是的话 `./run.sh realtime-start`。

**Q：文件树是空的，但任务显示 ✓？**
说明目录存在但里面没文件（可能是上传中断）。重新点一次该任务会重新拉取。

**Q：预览显示「服务器未安装 LibreOffice」？**
Office 格式需要它转 PDF。执行 `./run.sh soffice-install` 安装，**不需要重启服务**（每次预览实时检测）。

**Q：为什么有些任务置灰点不了？**
那是「未完成」的任务——沙箱还没跑完，OBS 上没东西可下。等它跑完再点。

**Q：交付物会一直留在磁盘上吗？**
目前**不会自动清理**。单任务上限 2 GiB，超了会删除并标「体积超限」。缓存盘空间需要留意。

**Q：下载失败要重试几次？**
自动重试最多 3 次，之后标「已跳过」。但你点击会**清零重试次数**重新排队，所以手动重试不受这个限制。
