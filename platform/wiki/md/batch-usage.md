# 批量实验使用说明

批量实验用来回答一类问题：**同一份测试集，换不同的 Harness 或不同的模型，效果差多少？**

它的矩阵是两条**互相独立**的轴：

```text
Harness 列表  ×  模型列表  ×  重复次数
（跑什么框架）    （跑什么模型）   （同一组合跑几轮）
```

两条轴做纯笛卡尔积 —— 列表里有几个 Harness、几个模型，就生成「Harness 数 × 模型数」个子任务，每个子任务内部再把整份测试集跑一遍。

> 举例：2 个 Harness（claude-code、opencode）× 1 个模型（glm-5.3）× 1 次重复 = 2 个子任务；测试集 3 条样本 → 总共 6 个任务。

---

## 1. 先准备数据集

批量实验的测试集只能来自「数据集管理」里登记过的条目。一条登记固定了样本目录和相关 OBS 路径，实验只引用它、不再单独传路径，保证同一个数据集在不同实验里口径一致。

「数据集管理 → 新建」需要填：

| 字段 | 说明 |
|---|---|
| 任务名称 | 展示用名称 |
| 用户 Config 目录（必填） | 样本配置文件（`task_configs/*.json`）所在 OBS 目录。**没填这条无法作为测试集** |
| 技能目录 / Agent 目录 | 对应 `skills/`、`agents/` 目录 |
| 用户 Profile 目录 | `user_profile.json` 等用户资料所在目录 |
| 默认技能 | 逗号分隔的技能名，会写进子任务配置 |
| 轨迹保存路径 | 可选。批量里只当前缀用，后端会按子任务再拼 `traj_<task_name>` |
| 样本数（`data_total`） | **务必填准确**，批量页的任务数、进度分母都靠它 |

> 样本数留 0 不会报错，但实验页的「任务数 / 进度」会失真（显示为 0），因为子任务执行时是「不限制条数」跑完全部文件。若数据集确实不填样本数，可以在「高级配置 → 任务总数」里显式填一个数把分母补回来。

---

## 2. 新建批量实验

入口：左侧菜单「批量实验」→ 右上「新建批量实验」。页面分三步：**配置实验 → 矩阵预览 → 确认创建**。

顶部三个必填项：实验名称、测试集（数据集）、任务数（由数据集自动带出）。

### 2.1 四个配置 Tab

| Tab | 配什么 |
|---|---|
| **Harness 类型** | Harness 轴：类型 / 配置方案 / 已发布版本 / 镜像 / 沙箱配置。每个 Harness 是矩阵的一列 |
| **模型配置** | 模型轴：Base URL / API Key / API 类型 / 模型 ID。**这条轴独立于 Harness，列表里的每个模型都会在每个 Harness 上各跑一遍** |
| **用户模拟配置** | `user_simulator` / `evaluator` 等 Agent，通用配置，作用于所有子任务 |
| **批量任务配置** | 队列并发、独立并发、重复次数、长尾跳过 |
| **高级配置** | 沙箱最大存活、起始索引、**任务总数**、代码仓、Key 追加后缀、本地代理 |

几点容易混淆的地方：

- **模型不隶属于 Harness。** 想让 glm-5.3 同时跑 claude-code 和 opencode，只加**一次**模型即可，不需要在每个 Harness 下各配一遍。
- **Base URL 带不带 `/v1` 都行。** 创建任务时会按各 Harness 的规则自动解析：claude-code 会剥掉 `/v1`、openclaw 会补上 `/v1`，其它 Harness 各有各的写法。
- **API 类型**决定协议（`anthropic-messages` / `openai-completions`），不同 Harness 落到配置文件里的位置不同，填错会连不上模型。
- **配置方案/版本只能选已发布的。** 方案没有已发布版本时无法用于实验，需先到「配置工作台」发布。
- **模型列表不能为空。** 空列表会被拦截 —— 没有模型的实验会退化成 Harness 模板里的占位模型，跑出来的数据不可用。

### 2.2 任务总数（高级配置）

「高级配置 → 任务总数」控制**每个子任务跑测试集里的几条**：

| 取值 | 含义 |
|---|---|
| `0`（默认） | 按数据集的样本数（`data_total`）跑 |
| `N > 0` | 只跑前 N 条，用于小样本冒烟 / 截断长数据集 |

它和「起始索引」配合使用：从第 `start_index` 条开始，取 `N` 条。

> 注意批量里的 `0` 是「按样本数」，不是单任务页的「不限制」。批量里若真的不限条数，进度分母会退回实际文件数，与实验页展示的任务总数对不上。

右侧「总执行实例数」会跟着这个值变化，填了 N 以后按 `Harness 数 × 模型数 × 重复次数 × N` 计算。

### 2.3 右侧矩阵预览

- 列 = Harness，行 = 模型，格子全打勾（纯正交）。
- 「子任务数」= Harness 数 × 模型数 × 重复次数；「总执行实例数」= 子任务数 × 每子任务样本数（即上面的任务总数口径）。

### 2.4 队列与并发

整批实验共用一条自动创建的队列（`batch-<实验ID>`），吞吐由两级并发相乘：

```text
同时运行的子任务数 = min(平台全局上限 QUEUE_MAX_CONCURRENT, 队列并发)
同时运行的沙箱数   = 上面的结果 × 独立并发(concurrent_num)
```

- **队列并发**：这条队列同时放行几个子任务（默认 10）。
- **独立并发**：每个子任务内部同时开几个沙箱。
- **长尾跳过**：队列里剩余任务已喂不满一轮并发时，额外放行一个，避免尾部拖很长。
- **重复次数**：同一组合跑几轮，用来观察稳定性，会乘进总任务数。

总任务数超过 10 万会被拒绝创建。

## 3. 创建后会发生什么

- 每个「Harness × 模型 × 轮次」组合生成一个**子任务**，命名规则 `实验名-配置N`，内部 `task_name` 为 `<实验ID>-cN`。
- 子任务与手工创建的任务**完全无差别**：同样的详情页、日志、轨迹、产物、导出。
- 创建时只写配置、秒级返回；点击实验详情「更多 → 启动队列」后才开始拉沙箱执行。
- 子任务里的模型 Key 会按配置的「Key 追加沙箱后缀」策略处理（自部署模型开、第三方模型关）。

## 4. 实验详情页

三个 Tab：

**执行概览** —— 已完成 / 运行中 / 排队中、成功率、整体进度；下方是每个子任务的进度表（含状态、DONE 数、任务进度）。

> **成功率 = 完成口径**（流水线正常跑完 ÷ 已结算）；下方小字另给 **DONE 口径**作参考。
> 两者不要混淆：DONE 是 agent 自己打的【Task_Done】标记，很多任务类型根本不会打，
> 拿它当成功率会系统性偏低。

**结果对比** ——

- 上方「关键指标对比」：按子任务一行，可切「完成率 / DONE 率」两种口径。
  - 完成率 = 流水线正常跑完的比例（不代表做对了）
  - DONE 率 = agent 自己打的【Task_Done】标记占已结算任务的比例，更接近「真的做完了」
- 下方「逐样本横向对比」：每行一条样本、每列一个子任务，格子里是等级与评分，点击可跳到该任务详情。

> **Token 统计**：对比表里的「调用次数 / 输入 Tokens / 输出 Tokens / 总 Tokens」来自
> 网关（llm_proxy_lite）的用量摘要，前提是子任务开启了「高级配置 → 启动本地代理」，
> 且轨迹已下载到本地缓存。显示 `—` 表示没有可统计的数据（未开网关或缓存未下载），
> 与「消耗为 0」不是一回事。

**详情** —— 创建时的完整参数，按创建页的五个 Tab 分组展示（Harness / 模型 / 用户模拟 / 批量任务 / 高级）。Key 一律掩码显示。

轨迹与会话等级（L0 ~ L3）的含义同单任务：L0 有轨迹；L1 工具调用 ≥3 且出现过纯文字回复；L1.5 有 evaluator 裁决；L2 首轮 completion ≥ 0.5；L3 首轮 completion = 1。

## 5. 运行管理

实验详情右上「更多」：

| 操作 | 语义 |
|---|---|
| **启动队列** | 把「待启动 / 已停止」的子任务全部入队，按顺序放行 |
| **暂停调度** | 队列不再放行新任务，**已在跑的不打断** |
| **继续执行** | 清除暂停位并立即触发一次调度 |
| **重跑失败样本** | 把「还有失败样本」的子任务重新拉起。**是增量的**：已成功的样本会被跳过，只重跑失败的那些，不会整份测试集重来 |
| **复制实验** | 新建页预填原配置，**模型与 Agent 的 Key 会一并继承**（显示为掩码），确认后即可创建 |
| **取消实验** | 停掉所有非终态子任务，并暂停队列 |
| **删除实验** | 只删实验与编组关系，**子任务一律保留**（它们有日志、轨迹、产物） |

## 6. 常见问题

**Q：某个子任务「没有模型」/ 创建参数里模型配置是空的？**
先检查模型列表是否为空。旧版本允许 Harness 不配模型、退回「兜底模型」，而兜底模型没有入口，最终会写进 Harness 模板里的占位模型。现在模型列表为空会直接拦截，不会静默建出坏任务。已建坏的实验请「复制实验」补上模型列表后重建。

**Q：同一个模型想在两个 Harness 上跑，要配两遍吗？**
不需要。模型轴与 Harness 正交，配一次就全部生效。

**Q：Base URL 必须带 /v1 吗？**
不必，带不带都能被各 Harness 正确解析。

**Q：子任务能单独改模型吗？**
不能。子任务的配置是创建时快照的，要改只能重建（复制实验）或在实验体外单独建任务。

**Q：实验的「成功率」和「结果对比」里的 DONE 率有什么区别？**
成功率是完成口径（流水线正常跑完），页面下方小字给出的 DONE 率是 agent 自己声明的完成比例。DONE 依赖 agent 打标记，很多任务类型不打，所以只作参考，不作为主指标。

**Q：能同时跑多少个沙箱？**
= min(全局上限, 队列并发) × 独立并发。全局上限由平台配置决定，触顶时队列会自动排队。
