# 资源看板使用说明

平台有两处看资源用得怎么样，**口径完全一致**：

- **首页「当前资源使用情况」**——一眼看此刻还剩多少。
- **侧栏「资源看板」**——看分布、排行和趋势。

## 一、核心口径

所有数字都按同一条规则算：

```
单实例占用 = 并发数（concurrent_num） × 单沙箱资源（cpu_request / memory_request）
```

- **哪些状态计入「已用」**：运行中 + 准备中。
  准备中的实例已经向集群申请了额度，所以也要算进去。
- **排队中单列**，不占资源——它还没开始。
- **总量**来自 `settings/sandbox/resource_pools.yaml`，按资源池（`sandbox_namespace`）分别配置。文件里没有的池显示「未配置」，而不是报错。
- 显示的「上限」是 `concurrent_num × cpu_limit`，也就是这些实例**最多**能吃到多少，用于判断是否顶着限制跑。

## 二、首页资源面板

三张卡片：

| 卡片 | 内容 |
|---|---|
| **CPU** | 已用 / 总量（核），下面一行是这些实例的上限之和 |
| **内存** | 已用 / 总量（GiB），同上 |
| **任务** | 运行中 / 准备中 / 排队中 / 已完成等状态计数 |

- 已用 + 排队 = 这批任务全部跑起来大概需要多少。
- 总量显示「未配置」表示 `resource_pools.yaml` 里没配这个池。此时百分比不显示，但已用数值仍然准确。

## 三、资源看板

侧栏「资源看板」（仅运行者及以上可见），顶部有 6 个 KPI：

| 指标 | 含义 |
|---|---|
| **总资源数** | 实例总数（所有状态） |
| **活跃实例** | 运行中 + 准备中，并列出排队数 |
| **运行中沙箱** | 所有运行中/准备中实例的并发数之和 |
| **CPU 占用** | 已用核数 / 总量，带百分比 |
| **内存占用** | 已用 GiB / 总量，带百分比 |
| **活跃用户** | 当前真正占用资源的用户数 |

下面是几张分布图：

- **用户资源占用排行**——按 CPU / 内存 / 沙箱数量切换排序，看谁占得多。
- **状态分布**——各状态各有几个实例。
- **Harness 类型 / 沙箱类型分布**——任务都跑在什么环境上。
- **OS 资源对比**——linux 与 windows 的占用对比。
- **资源池占用**——每个 namespace 的已用 / 总量。

## 四、趋势图为什么是「估算」

看板没有历史采样表。趋势是用每条实例的 `started_at` / `stopped_at` **扫描线重建**出来的：

- 在时间轴上把每个实例的占用区间累加，得到每个时间点的总占用。
- 因此响应里标注 `source="estimated"`。
- 有些实例缺 `stopped_at`（比如异常退出又没同步到状态），重建时按最多 24 小时截断，避免一条无限长的平线污染整张图。
- 参与重建的行数上限是 5000 条。超出时只取最近的，并在响应里标记 `truncated`——此时曲线前段可能不全。

**要点**：趋势适合看大致形状（什么时候忙、什么时候闲），不适合当计费依据。

## 五、数据从哪来

```
resource_pools.yaml      → 总量分母（每个 namespace 一份）
task_instances           → 每条实例的并发数与单沙箱资源
config_snapshot          → 解析出 sandbox_type / harness_type / 资源
```

- 沙箱资源取自实例创建时的 **config 快照**，所以后来改沙箱配置不会影响历史实例的统计。
- 总量是文件配置，改完刷新即可（后端有缓存，配置变更才会重读）。
- 首页每 10 秒刷新一次，资源看板按需刷新（可点右上角「刷新」）。

## 六、常见问题

**Q：总量显示「未配置」怎么办？**
在 `settings/sandbox/resource_pools.yaml` 里补上对应 namespace 的 `total_cpu` / `total_memory_gb`。没配也能看到已用，只是没有百分比。

**Q：已用比实际感受少？**
检查是否有实例处于「准备中」但还没真正申请到资源，以及是否有 `stopped_at` 缺失的历史实例。统计只对 `running` / `preparing` 计数。

**Q：为什么看板里有些任务不在排行里？**
排行只看**占用资源**的实例（运行中 + 准备中）。已完成、已停止的不参与。

**Q：改了沙箱配置，为什么看板数字没变？**
历史实例用的是创建时的配置快照。新配置只影响之后创建的实例。
