# 文档中心使用说明

## 一、写一篇文档

侧栏 **文档中心 → 新建文档**（仅管理员可写）。

1. **标题**：列表和通知里显示的名字。
2. **文件名**：决定链接地址 `#/wiki/<文件名>`。留空则由标题自动生成，**创建后不可改**。
3. **分类 / 标签**：用于筛选；分类可排序，标签可自由创建。
4. **关联类型 / 关联对象**：可选。关联到某个镜像、代码仓、Harness 版本等，
   方便日后按版本反查「这一版改了什么」。
5. **正文**：**所见即所得**编辑器。工具栏可直接插入标题、列表、表格、代码块、公式；
   表格支持拖拽列宽、增删行列、对齐。

写完点 **保存**。正文会立即写入磁盘，无需重启，也无需导入。

> 编辑器底层仍然是**标准 Markdown**，数据库/文件里存的就是 `.md` 文本。
> 所以 Git diff、IDE 编辑、`git log` 回滚都照常可用。

### 插入图片

**把截图直接粘贴进正文**，或拖拽图片文件进来，即可自动上传。

上传后图片会自动：

- **压缩成 WebP**（最长边 1600px，质量 82），截图通常能压到原图的 1/5；
- 存到 `platform/wiki/assets/`，文件名用随机 UUID；
- 插入为图片块，**拖拽右下角手柄可调整显示比例**。

支持 png / jpg / gif / webp。**动画 GIF 原样保留**（转码会丢动画），体积可能偏大。
不支持 SVG。

> **图片比例存在 Markdown 的 alt 字段里**，形如 `![0.62](/api/wiki/assets/xxx.webp)`，
> 表示按 62% 宽度显示。因此图片没有替代文本，这是该方案的取舍。
>
> `wiki/assets/` **不随 Git 同步**（避免仓库被二进制撑大）。换机器或备份时，
> 需要单独拷贝这个目录，否则文档里的图片会显示不出来。

## 二、广播推送给所有用户

文档保存后，在**详情页右上角**点 **「发布为通知」**。

弹窗里：

- **推送给所有用户**：勾选 → 生成一条全局通知；不勾选 → 只标记「已发布」，不打扰任何人。
- **通知标题**：默认取文档标题，可改。
- **级别**：普通 / 成功 / 提醒 / 重要，决定通知卡片左侧的颜色条。
- **正文快照**：默认是文档当前正文，可以发布前临时删减。

确认后，所有登录用户的顶栏铃铛会显示未读数（最长 60 秒内出现）。
点击铃铛进入**通知中心**，可查看全文、标记已读、跳转到对应文档。

**注意**：通知里存的是**发布那一刻的正文快照**。之后修改文档不会改动已发出的公告 ——
如果需要更正，重新发布一次更稳妥（旧公告可在「我发出的」里撤回）。

## 三、管理已发布的通知

通知中心 → **我发出的**（管理员可见）：

- 看每条公告的**已读人数 / 总用户数**。
- **撤回**：所有用户的列表里立即消失（软删，已读记录保留）。

## 四、文档存在哪里

```
platform/wiki/
  ├── md/<文件名>.md     正文 + frontmatter（内容的唯一真相）
  └── index.db           索引，删掉会自动从 md 重建
```

- 界面编辑器读写的就是这些 `.md` 文件。
- 也可以直接用 IDE 改文件，刷新页面即生效。
- 整个 `platform/wiki/` 目录可以整体拷贝来同步或备份。
- 想看历史、diff、回滚：

```bash
git log -p -- platform/wiki/md/
git diff HEAD~1 -- platform/wiki/md/openclaw-v3-release.md
git checkout HEAD~1 -- platform/wiki/md/openclaw-v3-release.md
```

## 五、已知限制

- 暂无文档版本历史 —— 用 `git log` 代替。
- 图片存 `wiki/assets/`，不随 Git 同步，需单独备份。
- 通知只有站内渠道，不含邮件 / Webhook。
